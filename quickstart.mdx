In this guide you'll make your first QUEUE API call — creating a repair ticket — in under five minutes. By the end you'll have a working request, understand the response envelope, and know how to verify the repair was created by listing your repairs.

<Note>
  **Prerequisites:** You need a QUEUE account on a plan that includes REST API access, and you must be able to log in as a company administrator to generate a token. If you're unsure whether your plan includes the API, contact your account manager.
</Note>

<Steps>
  <Step title="Get your API token">
    Before making any requests, you need a Bearer token. Head to your QUEUE dashboard, open **Profile** (Perfil) → **API Keys** (Chaves de API / API Keys), and create a new key with a name like `"Quickstart Test"`.

    Copy the token immediately — it is shown only once. For full details on token generation and scopes, see the [Authentication](/authentication) page.
  </Step>
  <Step title="Set your base URL">
    All QUEUE API endpoints share a single base URL:

    ```text
    https://queue.pt/api/v1
    ```
  </Step>
  <Step title="Create your first repair">
    Send a `POST` request to `/repairs` with your customer details, device, and service information:

    ```bash
    curl -X POST 'https://queue.pt/api/v1/repairs' \
      -H 'Content-Type: application/json' \
      -H 'Authorization: Bearer queue_xxxxxxxxxxxxxxxxxxxxxxxx' \
      -d '{
        "customer": {
          "full_name": "João Silva",
          "email": "joao@example.com"
        },
        "device": "Samsung Galaxy S23",
        "service": "Troca de bateria",
        "description": "Bateria não aguenta 1 dia."
      }'
    ```

    A successful request returns HTTP `201 Created`.
  </Step>
  <Step title="Read the response">
    The API responds with the newly created repair object wrapped in the standard QUEUE envelope:

    ```json
    {
      "ok": true,
      "data": {
        "id": "uuid",
        "repair_number": 123,
        "repair_number_formatted": "R-0123",
        "created_at": "2026-08-19T12:00:00.000Z",
        "company_id": "uuid",
        "customer_id": "uuid",
        "customer_is_new": true,
        "device": "Samsung Galaxy S23",
        "service": "Troca de bateria",
        "serial": null,
        "password": null,
        "description": "Bateria não aguenta 1 dia.",
        "accessories": null,
        "status": "uuid",
        "warranty_status": null,
        "scheduled_at": null
      }
    }
    ```

    Key fields to note:

    | Field | Description |
    | --- | --- |
    | `ok` | `true` confirms the request succeeded. |
    | `data.id` | The UUID of the repair — use this to retrieve, update, or reference the ticket in subsequent API calls. |
    | `repair_number_formatted` | The human-readable repair reference (e.g. `R-0123`) displayed in the QUEUE dashboard and on customer-facing documents. |
    | `customer_is_new` | `true` if this is the first repair for this customer's email address; `false` if they already exist in your company's records. |
  </Step>
  <Step title="List your repairs">
    Confirm the repair was created by fetching your repairs list:

    ```bash
    curl -X GET 'https://your-domain.com/api/v1/repairs' \
      -H 'Content-Type: application/json' \
      -H 'Authorization: Bearer queue_xxxxxxxxxxxxxxxxxxxxxxxx'
    ```

    The response returns a paginated collection of repairs. Your new ticket — identified by `repair_number_formatted` — should appear at the top of the list, ordered by creation date descending.
  </Step>
</Steps>
